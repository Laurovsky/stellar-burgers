## Этапы работы:

1. Разверните проект и ознакомьтесь с кодом. Все необходимые вам компоненты уже созданы и лежат в папке `src/components`

2. Настройте роутинг.

3. Напишите функционал запросов данных с сервера, используя `Redux` и глобальный `store`. Сами "ручки" уже прописаны и лежат в `utils/burger-api.ts`

4. Настройте авторизацию и создайте защищённые роуты.

## Важно:

Для корректной работы запросов к серверу необходимо добавить переменную BURGER_API_URL в окружение. Сама ссылка находится в файле `.env.example`.


## Тесты

Установка зависимостей: `npm ci`.

- `npm test -- --runInBand` — юнит-тесты редьюсеров ingredients и burgerConstructor.
- `npm run test:coverage -- --runInBand` — покрытие двух слайсов; HTML-отчёт находится в `coverage/index.html`.
- `npx playwright install chromium` — установка браузера перед первым запуском.
- `npm run e2e` — интеграционные тесты конструктора.
- `npm run e2e:ui` — интерактивный запуск Playwright.
- `npx playwright show-report` — просмотр последнего отчёта.

Playwright самостоятельно запускает приложение на порту 4000. Перед запуском тестов этот порт должен быть свободен. Адрес API задаётся в настройках тестового сервера, поэтому для тестов файл `.env` не требуется.

Ингредиенты берутся из `tests/fixtures/ingredients.har` через `routeFromHAR`. Ответы пользователя и заказа находятся в `tests/fixtures/user.json` и `order.json`. Токены подставляются в cookie и localStorage перед открытием страницы. Реальные запросы к API блокируются.

Проверяются добавление и замена булок, добавление начинки и соуса, открытие деталей ингредиента, закрытие крестиком, оверлеем и Escape, состав и авторизация запроса заказа, номер заказа, очистка конструктора и закрытие окна заказа. Юнит-тесты вызывают редьюсеры напрямую для всех обрабатываемых экшенов, включая асинхронные стадии и неизвестный экшен.
